# Электронная платёжная система

Полный исходный проект Android-клиента на Kotlin и сервера Ktor с PostgreSQL. Интерфейс на русском: регистрация, вход, баланс, переводы, оплата услуг, виртуальные карты, поиск, история операций, профиль и тёмная тема.

**Область применения:** учебная система с внутренними демонстрационными средствами. Переводы действительно изменяют остатки в PostgreSQL и создают историю, но не отправляют деньги в банк. Виртуальная карта — идентификатор внутреннего кошелька. В проекте нет эквайринга, ввода PAN/CVV и подключения реальных банков. Это работающее приложение для курсовой; готовность к эксплуатации с реальными деньгами не заявляется.

## Быстрый запуск

Требования: JDK 21, Docker Engine / Docker Desktop, Android Studio и Android SDK 35. Gradle Wrapper включён. При первом запуске нужен доступ к Google Maven, Maven Central и Gradle distributions. На Windows используйте `gradlew.bat`, на macOS/Linux — `./gradlew`.

1. Скопируйте `.env.example` в `.env` и задайте случайные `DB_PASSWORD` и `JWT_SECRET` (не менее 32 символов). `DEMO_MODE=true` включает только локальные демонстрационные аккаунты.
2. В корне проекта выполните:

```powershell
docker compose up --build -d
curl.exe http://localhost:8080/health
```

3. Откройте корень проекта в Android Studio. Выберите JDK 21 для Gradle, установите SDK 35 и запустите модуль `androidApp` на эмуляторе Android 8.0+.
4. Debug-клиент использует `http://10.0.2.2:8080/api/`, то есть сервер на компьютере из стандартного Android Emulator.

Демонстрационные аккаунты:

| Email | Пароль | Телефон | Начальный баланс |
|---|---|---|---|
| alice@example.test | DemoPassword123! | +79990000001 | 1 000 ₽ |
| bob@example.test | DemoPassword123! | +79990000002 | 1 000 ₽ |

Средства создаются только при первом создании demo-аккаунта, перезапуск сервера не пополняет баланс. Новая регистрация создаёт кошелёк с нулевым остатком. Пополните его переводом с демонстрационного аккаунта. Услуга «Мобильная связь» имеет код `mobile`; найдите её по слову «Мобильная».

Для перевода «по карте» Борис создаёт виртуальную карту, копирует её UUID из раздела «Карты» и передаёт Алисе. Последние четыре цифры служат только для отображения и не являются адресом перевода.

Остановка: `docker compose down` сохраняет данные в Docker volume. Не добавляйте `-v`, если хотите сохранить баланс и историю.

## Запуск без Docker

Создайте отдельную PostgreSQL-базу и пользователя с правом создания таблиц в этой базе. Flyway автоматически применит `server/src/main/resources/db/migration/V1__initial.sql` при запуске.

```powershell
$env:JAVA_HOME='C:\Program Files\Java\jdk-21'
$env:DB_URL='jdbc:postgresql://localhost:5432/eps'
$env:DB_USER='eps'
$env:DB_PASSWORD='your-local-password'
$env:JWT_SECRET='replace-with-a-long-random-secret-at-least-32-characters'
$env:DEMO_MODE='true'
.\gradlew.bat -PbackendOnly :server:run
```

`-PbackendOnly` исключает Android-модуль: сервер и общая бизнес-логика собираются без Android SDK. Для передачи готовой серверной сборки: `gradlew.bat -PbackendOnly :server:installDist`; запуск — `server/build/install/server/bin/server.bat` с теми же переменными окружения. Переменная `PORT` по умолчанию равна 8080.

## Сборка и проверки

```powershell
# Domain + security + integration tests. Docker must be running for Testcontainers.
.\gradlew.bat -PbackendOnly :domain:test :server:test
# Android unit tests, APK and static Android checks
.\gradlew.bat :androidApp:testDebugUnitTest :androidApp:assembleDebug :androidApp:lintDebug
```

APK: `androidApp/build/outputs/apk/debug/androidApp-debug.apk`.

Для интеграционных тестов без Docker задайте `TEST_DB_URL`, `TEST_DB_USER`, `TEST_DB_PASSWORD`. **Используйте отдельную тестовую базу:** перед каждым сценарием тесты очищают её таблицы. Отсутствие Docker не приводит к скрытому пропуску тестов — сборка завершится ошибкой, если альтернативная тестовая база не указана.

```powershell
$env:TEST_DB_URL='jdbc:postgresql://localhost:5432/eps_test'
$env:TEST_DB_USER='eps_test'
$env:TEST_DB_PASSWORD='test-only-password'
.\gradlew.bat -PbackendOnly :server:test
```

Сводка фактически выполненных проверок находится в `docs/VERIFICATION.md`; автоматические сценарии и ручная приёмка — в `docs/TESTING.md`.

## Структура

```text
contracts/   JSON DTO на Kotlin Serialization — контракт HTTP
 domain/     Чистые Kotlin-модели, интерфейс репозитория, use cases, правила денег
 server/     Ktor API, JWT, PostgreSQL/HikariCP, миграции Flyway, тесты
 androidApp/
   data/         Ktor Client, DTO → domain mapping, Android Keystore
   domain/       Находится в отдельном Gradle-модуле :domain
   presentation/ Compose, StateFlow, MVVM, SavedStateHandle
   di/           Hilt dependency injection
 docs/        API, архитектура, соответствие требованиям, проверки
```

Зависимости: Presentation → Domain; Data → Domain + Contracts; Hilt связывает реализацию репозитория с интерфейсом. Domain не зависит от Android, Ktor или JSON. Kotlin используется для всего прикладного кода клиента, сервера и тестов; SQL/YAML/XML применяются для схемы и конфигурации. Firebase отсутствует.

## Поиск и сохранение состояния

Поиск выполняется по кнопке «Найти» или действию клавиатуры. Получатели находятся по **полному** телефону/email, услуги — по части названия. Это не публичный каталог всех пользователей. Нажатие результата сохраняет именно выбранный объект в серверную историю и открывает перевод. История содержит максимум 10 объектов; повторный выбор перемещает объект вверх. Ввод запроса сам по себе не добавляет запись.

`SavedStateHandle` сохраняет запрос, последнюю попытку, фильтры и поля перевода. Изменение запроса отменяет предыдущий поиск; номер поколения защищает от устаревших результатов. «Очистить» появляется только для непустого запроса, очищает его, убирает результаты и закрывает клавиатуру. При фокусе на пустом поле показывается история. «Обновить» повторяет последний запрос. Пароль не сохраняется в SavedStateHandle.

## Надёжность платежей и сессий

- Деньги — `Long` в копейках / PostgreSQL `BIGINT`; дробные копейки и отрицательные суммы отклоняются.
- Списание, зачисление и запись операции выполняются одной транзакцией. Строки счетов блокируются `FOR UPDATE` в общем порядке UUID.
- Ключ `Idempotency-Key` и отпечаток запроса обеспечивают один перевод при повторных запросах. Повтор ключа с другим содержимым возвращает 409.
- Клиент шифрует незавершённый запрос и ключ **до** отправки. После timeout/перезапуска повторяет тот же запрос; поля заблокированы до подтверждения результата. Нельзя начать другой перевод, пока результат не известен.
- Баланс доступен только через аутентифицированные маршруты. Сервер определяет владельца по JWT, а не из тела запроса. Удаление чужой карты запрещено.
- Пароли: PBKDF2-HMAC-SHA256, случайная соль, 600 000 итераций. JWT: проверка подписи, issuer, audience, срока действия и серверной сессии. Сессия действует 1 час; после истечения нужен новый вход. Logout отзывает текущую сессию.
- Токен и незавершённый платёж шифруются AES-GCM ключом Android Keystore; backup приложения отключён. В HTTP-логах не печатаются токены и пароли.
- JDBC работает на `Dispatchers.IO`, вычисление password hash — на `Dispatchers.Default`, сетевые вызовы Ktor Client асинхронны.

## Настройка для развёртывания

Отключите `DEMO_MODE`, используйте отдельную пустую базу, случайные секреты вне Git, HTTPS reverse proxy, резервное копирование с проверкой восстановления, ограниченный доступ к PostgreSQL и мониторинг. Лимиты запросов в текущем сервере действуют на экземпляр; при нескольких экземплярах нужен общий limiter. Не доверяйте клиентскому IP из произвольных forwarded headers.

Release-клиент запрещает cleartext HTTP. Укажите реальный HTTPS адрес:

```powershell
.\gradlew.bat :androidApp:assembleRelease -PapiUrl=https://your-domain.example/api/
```

Release-подпись задаётся владельцем проекта через Android Studio/CI; ключи подписи не включены. Домен `payments.example.invalid` — намеренно неработающее значение по умолчанию. Нельзя использовать демонстрационные логины или `.env.example` как боевые секреты.

До использования реальных денег необходимы: подключение платёжного провайдера и его sandbox, webhooks с проверкой подписи, сверка/возвраты, полноценный бухгалтерский ledger и аудит, подтверждение владения телефоном/email, дополнительные факторы для платежей, восстановление доступа, независимое тестирование безопасности и нагрузочные испытания. Эти интеграции не имитируются ответом «успех».

## Источники требований

«Методические указания КР новые.pdf», страницы 32–33: Kotlin, русский интерфейс, сервер/БД и точное поведение поиска. Переданная курсовая Юсубова описывает приложение «Музыка», поэтому её предметная область не перенесена; приложение реализует вашу тему «Электронная платёжная система». Макеты музыкального приложения не являются макетами платёжной системы.

Технические справочники: [JWT в Ktor](https://ktor.io/docs/server-jwt.html), [настройка Compose compiler](https://developer.android.com/develop/ui/compose/setup-compose-dependencies-and-compiler). Зависимости закреплены в Gradle-файлах; обновление версий требует повторного прогона тестов.
